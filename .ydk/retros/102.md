## Analysis (Claude Code session, no API provider)
### Patterns
- An owner decision (discard "never throw") was recorded as ADR-023 first and then split into four ordered tasks (types, size limit, stage guards, docs). The order kept every PR small and green.
- The old guard tests were rewritten to assert the throw, not deleted. That closed two hidden #37 gaps: a metadata fault returned the wrong SubjectDirection, and a body fault leaked the body as an attachment.
- The per-part catch sites were narrowed to seven content exception types. Tests check both directions: a content error stays its warning, any other type is wrapped.
- GoldenKit kept the same check count by replacing no_internal_error with no_throw one for one.
- ADR-023 PR merged before its decision commit was pushed, so a follow-up PR (#101) was needed for owner approvals.
- Stale references (the deleted input-too-large manifest, the internal_error warning, "Target; not implemented" notes) were left behind in plans and manifests until a docs pass (#107).

### Rule suggestions
- When removing a warning or manifest, grep the docs, plans and manifests in the same PR.
- Push all decision commits before asking for an ADR merge.
- Parallel tasks editing shared manifests (library-surface.yaml) conflict; prefer one owner task per manifest per wave.

### Summary
Error-model epic replaced silent internal_error warnings with typed exceptions while keeping content errors as warnings. Open points: detect-stage throws record no telemetry (ADR-021 tag set), and ADR-004 is kept as history.
