## Analysis (Claude Code session, no API provider)
### Patterns
- Harness (#48) and large-file pass (#49) produced the inputs for the limits task (#51); measured M (1.3-4.2x) drove the sizing note.
- The owner overrode the data-derived maxInputBytes default: 150 MiB -> 500 MiB (OWNER-SET). Measured M at 500 MiB is still missing, because the M figure comes from the 150 MiB run.
- A sweep test named DefaultBoundary would have allocated 500 MiB in CI after the default change, so it was replaced with a constant check. Tests must not scale with tunable defaults.
- Sweep runs without a DOP 1 baseline emitted meaningless efficiency until the fix in #110 (null efficiency).
- A semantic conflict between parallel PRs broke main (XFields removal vs a new test, fixed in #92).

### Rule suggestions
- Heavy perf/size tests use explicit small limits, never library defaults.
- Owner-set limits must be labeled OWNER-SET, and the provenance of the measurement must be stated.
- After a batch merge, build main before starting the next wave.
